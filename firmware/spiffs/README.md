# Data partition contents

Everything in this folder is packed into a LittleFS image and flashed to the
`storage` partition. It's what the device reads at runtime.

> ## ⚠️ The audio here is generated — don't put your recordings in this folder
>
> `tools\build-audio.ps1` encodes `assets/audio-src/` into here, and **prunes
> any audio whose master is missing**. Drop a clip straight into this folder and
> the next build deletes it.
>
> Put your recordings in **`assets/audio-src/`**, in the same layout (`cd/`,
> `Program/`, and the reward sounds at the top level), then run the script. It
> encodes to MP3, keeps each file's sample rate, and loudness-matches everything
> so takes recorded at different times sit together. See
> [`docs/audio-roadmap.md`](../../docs/audio-roadmap.md).
>
> `www/` is real source and is never touched.

## What's here

- `www/` — the setup and band-manager web page, its favicon and logo. These are
  served straight off the filesystem, so the UI can be changed (or updated over
  the air) without rebuilding the firmware.

## What's deliberately missing: the audio

**No audio is committed** — `.gitignore` excludes it, in both this folder and
`assets/audio-src/`. It splits into two groups with different answers:

**Reward sounds** (partition root) — `chime.wav`, `excellent.wav`, `foolish.wav`,
`hello.wav`, `operational.wav`, `startours.wav`, `walt-welcome.wav`,
`be-our-guest.wav`. These came from the
[Adafruit Magic Band Reader](https://learn.adafruit.com/magic-band-reader)
project — **download them from that guide.** They're park audio bundled with it,
so they aren't redistributed here. The list lives in
[`main/sounds.c`](../main/sounds.c); edit it to match whatever you have.

**Countdown clips (`cd/`) and prompts (`Program/`)** — recorded by the project's
author, so they're one person's voice. Record your own; that's most of the charm.

**The firmware runs fine without any of it.** A missing clip is treated as
"skip", so the device boots, reads bands, serves the web UI and keeps time with
an empty bank — it's just quiet. Add files and it finds its voice, one pool at a
time.

See the main [README](../../README.md) for the file names each pool expects, and
[`docs/countdown-recording-script.md`](../../docs/countdown-recording-script.md)
for the recording script.

### Format

Record masters as **mono 16-bit PCM WAV**. The build script handles the rest —
encoding, sample rate and levels — so you don't have to match anything by hand.

Two things it can't fix, so get them right at the mic:

- **`cd/` clips must all share one sample rate.** They're concatenated to build
  a sentence, and retuning the I2S clock mid-phrase is audible as a tick. The
  script pins `cd/` to one rate; recording them consistently avoids a resample.
- **Trim leading and trailing silence.** Timing between words comes from the
  clips themselves.

Levels don't need to match. The script loudness-matches every clip, which is
what lets takes from different sessions sound like one voice.

### Layout

Masters — **this is where your recordings go**:

```
assets/audio-src/
├── cd/                  countdown clip bank
├── Program/             spoken prompts for setup / program mode
└── *.wav                the reward sounds a band can be assigned
```

Build output, regenerated by `tools\build-audio.ps1`:

```
firmware/spiffs/
├── www/                 web UI (committed - real source)
├── cd/                  encoded countdown clips     (generated)
├── Program/             encoded prompts             (generated)
└── *.mp3                encoded reward sounds       (generated)
```

Paths in the firmware still say `.wav` (`sounds.c`, `config.h`). That's fine —
the extension is treated as a logical name and the other one is tried, so a clip
can ship as either format without touching the source.

## Note on over-the-air asset updates

The firmware can fetch individual files into this partition at runtime, which is
how new sounds reach a device that's already been given away.

That needs the files to be hosted somewhere **publicly readable** — the device
has no way to authenticate. Since this repository doesn't carry audio, OTA here
ships **firmware only** out of the box. If you host your own audio somewhere,
point the manifest's `assets.base_url` at it; see
[`docs/ota-setup.md`](../../docs/ota-setup.md).
